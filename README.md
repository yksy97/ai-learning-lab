# GAN Visualizer

2次元のデータで生成モデルを学習させ、その過程をブラウザ上でリアルタイムに見るためのローカルアプリです。
**GAN（敵対的生成ネットワーク）** と **自己回帰 Transformer** の2つを実装していて、同じ分布で並べて比べることもできます。
ニューラルネットの順伝播・逆伝播・Adam、Transformer の注意機構まですべて素の JavaScript で書いてあるので、**npm install は不要**で、外部ライブラリにも依存しません。

![GAN Visualizer の画面](docs/screenshot.png)

## 起動

Node.js 18 以上が必要です。

```bash
cd ~/Developer/gan-visualizer
npm start            # = node server.js
```

ブラウザで http://localhost:8080 を開きます。ポートを変えたいときは `PORT=3000 npm start` を使います（8080 が使用中なら、空いている次のポートを自動で使います）。

Node が使えない環境では `cd public && python3 -m http.server 8080` でも動きます。

画面上部のタブで4つのページを切り替えます。選んでいる分布はページをまたいで引き継がれます。

| ページ | 内容 |
|---|---|
| はじめて（偽札と警察） | GAN を「偽札職人（G）と警察（D）の勝負」にたとえて、9 ステップの紙芝居形式で順番に見せる。モード崩壊と勾配消失も体験できる。**最初はここから** |
| GAN | Generator と Discriminator の攻防。点がアメーバのように動いて本物に近づく |
| 自己回帰 Transformer | 点をトークン列にして「次のトークン」を予測。学習した確率 p(x) と、1点ずつ生成する過程、アテンションを表示 |
| 比較 | 同じ分布・同じステップ数で両方を学習させ、品質（precision）と網羅性（recall）を並べる |

## GAN ページ

| 要素 | 意味 |
|---|---|
| 青い点 | 本物のデータ（学習の目標となる分布） |
| 橙の点 | Generator が生成した点。固定した 500 個の z から作っているので、同じ点が動いていく様子を追える |
| 背景の色 | Discriminator の判定 D(x)。青いほど「本物」、橙ほど「偽物」と判定している |
| 薄い格子 | 潜在空間 z の格子を G で写したもの。G がノイズ空間をどう折り曲げているかが分かる |
| 矢印（オプション） | D の勾配。G の出力がどちらへ引っ張られるか |
| 損失グラフ | D と G の損失。点線は理論的な均衡値（2·ln2 と ln2） |
| D の出力グラフ | 本物と生成に対する D の平均出力。均衡すると両方 0.5 に近づく |

データ空間にマウスを乗せると、その位置での D(x) が表示されます。

## 自己回帰 Transformer ページ

各軸を 64 段階に区切り、1点を「x₁ の粗い位置・x₂ の粗い位置・x₁ の細かい位置・x₂ の細かい位置」の 4 トークン（語彙 8）で表します。
Transformer は直前までのトークンを見て次のトークンの確率を出し、p(x) = p(t₁)·p(t₂|t₁)·p(t₃|t₁,t₂)·p(t₄|t₁,t₂,t₃) を学習します。

| 要素 | 意味 |
|---|---|
| 背景の濃淡 | 学習した確率 p(x)（対数スケール）。64×64 のマス目がそのまま見える |
| 緑の点 | 祖先サンプリングで生成した点 |
| 1点ずつ生成する | 各トークンの条件付き分布を棒グラフで表示。データ空間には次の候補 8 個が色つきの帯で出る |
| アテンション | 各層・各ヘッドで、どの位置がどの入力トークンを参照しているか（因果マスク付き） |
| 負の対数尤度 | 1点あたりの NLL。点線は本物の分布のエントロピー（理論的な下限） |

データ空間をクリックすると、そのマスの確率がどのトークンの確率の積でできているかを表示します。
「トークンの順序」を「軸ごと」に変えると、x₁ を完全に決めてから x₂ を決める順番になります。

## 比較ページ

同じ分布・同じステップ数・同じバッチサイズで両方を学習させ、次の指標を並べます。

- **品質（precision）**：生成点のうち、本物の点の近くに落ちた割合
- **網羅性（recall）**：本物の点のうち、生成点の近くにある割合
- **覆えている山**：混合ガウス（8つのガウス・5×5 格子）で、十分な数の生成点が落ちている山の数

「近く」の判定には Kynkäänniemi et al. (2019) の改良版 Precision / Recall（k = 3）を使っています。点を広くばらまくと網羅性だけ高く出るので、「覆えている山」と合わせて見てください。

なお、2次元は自己回帰モデルに有利な舞台です（全 4096 マスを数え上げられる）。ここで Transformer が勝つからといって、画像のような高次元でも同じとは限りません。

## 試してみると面白いこと

- **モード崩壊**：GAN ページの「円周上の8つのガウス」で G の学習率を 0.005〜0.01 に上げる
- **勾配消失**：GAN の損失を「ミニマックス」にして「渦巻き」などを学習させると、D が早々に勝ちすぎて G に勾配が届かず、生成点が表示範囲の外へ飛んだまま戻らないことがある（非飽和の損失が標準とされる理由）
- **表現力不足**：「渦巻き」で隠れ層を 1 層・16 ユニットにすると、形を真似しきれない
- **潜在次元**：ノイズ z を 1 次元にすると、G は 1 本の曲線しか描けない
- **GAN の「橋」**：比較ページの「5×5 格子のガウス」で、GAN の点が山と山のあいだに残る様子と、Transformer がマスごとに山を分けて覆う様子を見比べる
- **アテンションの役割分担**：Transformer ページで学習後にデータ空間をクリックし、各ヘッドがどのトークンを見ているかを確かめる

## 実装メモ

**GAN**

- G: `z (1/2/4次元) → [隠れ層 × depth, LeakyReLU] → x (2次元)`
- D: `x (2次元) → [隠れ層 × depth, LeakyReLU] → ロジット`
- 最適化は Adam（β1 = 0.5, β2 = 0.999）
- D の更新：`−log D(x_real) − log(1 − D(G(z)))` を最小化
- G の更新：非飽和版は `−log D(G(z))`、ミニマックス版は `log(1 − D(G(z)))` を最小化。勾配は D を通して G へ流すが、その際に D のパラメータは更新しない

**自己回帰 Transformer**

- 入力：`[BOS, t₁, t₂, t₃]`、予測：`[t₁, t₂, t₃, t₄]`（語彙 8、系列長 4）
- `トークン埋め込み + 位置埋め込み → [LayerNorm → 因果的マルチヘッド自己注意 → 残差 → LayerNorm → MLP(ReLU) → 残差] × 層数 → LayerNorm → 線形`（Pre-LN）
- 損失は交差エントロピー（= 負の対数尤度）、最適化は Adam（β1 = 0.9, β2 = 0.99）
- 8³ = 512 通りの接頭辞を一度に流して全ての条件付き分布を表にし、64×64 マスの p(x) と祖先サンプリングを計算
- 逆伝播は全パラメータについて数値微分と一致することをテストで確認している
